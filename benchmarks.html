The exams

We are not testing competitors. We are sitting the same exam they sat.

A benchmark is not a product. MEME is a hundred scripted situations with public code and public data, written by academics at KAIST and Tübingen. Every memory system runs the same hundred. Our store sits it too — before we change anything, and after — and the difference between those two numbers is the entire claim.

The alternative is what the field does now: each vendor invents its own test, scores itself, and asks to be believed. One company in this category publishes a table of results that appears on no leaderboard and in no paper, only on its own website, with a footnote saying to treat it as vendor-reported.

The main exam

What MEME actually asks.

Every other memory benchmark asks a version of "I told you something earlier — can you find it?" Those are solved. Systems score in the nineties, the differences are noise, and one of them has a measured six percent error rate in its own answer key.

MEME asks the question a company brain exists to answer: a fact changed — do you know what else is now wrong? Its hundred episodes are conversations spread over many sessions, with filler in between, where something stated early is revised later and other things depended on it.

It scores six things. Three are ordinary recall. The three that matter are these:

  • Cascade — a rule was stated, the thing it depended on changed. Does the store follow the rule to the new answer?
  • Absence — same change, but no rule covers the dependent. Does the store say it no longer knows, or confidently repeat the stale value?
  • Deletion — the user asked for something to be removed. Is it actually gone, or does it come back through a summary?

There is a filter that stops a system scoring by accident: to get credit for a change, it has to have known the original value first. You cannot pass by never having learned anything.

required: Thandrel Infra — the rule was stated, apply it ✓

Asked afterwards · absence

What is the CI configuration set to?

every system in the study: the old value, stated confidently ✗

required: "that depended on the deploy target and has not been re-established" ✓

Across six systems and a hundred episodes: 3% on cascade, 1% on absence. Not one practical configuration passes. The authors tried better prompts, deeper retrieval, less noise and a stronger answering model; none of it moved.

Why this one

Four reasons it is the right exam to be graded on.

It tests the product, not the plumbing

A company brain's job is to be right about a company that keeps changing. Pricing moves, the owner of a service changes, a policy is reversed. Recall benchmarks never test this. If we pass recall and fail this, we have built a search engine with extra steps.

It is unsolved and not saturated

Three percent and one percent. There is no ceiling effect to argue about and no crowd at the top. A real result here is visible from a distance, and the failure is structural rather than a tuning problem — the authors demonstrated that.

It has a cost column

The harness already tracks tokens by class per episode. The one configuration that does pass costs about seventy times the baseline and wrecks ordinary recall doing it. So the honest claim is never a score alone — it is a score at a price, which is the pair nobody publishes.

Anyone can check us

Code on GitHub, data on Hugging Face, a fixed judge, a documented adapter interface. We publish our runner and our raw output; if we are wrong, someone re-runs it and says so. That is the difference between a number and a claim.

The rest of the set

What else gets run, and what each one is for.

Session cost, under the public protocol

the bulk of the budget

Paired runs of the same coding task, with and without the memory layer, in isolated sessions on a pinned model, ten repetitions, graded by a program rather than an opinion — and the metric is dollars per solved task, so a tool cannot win by making the agent fail faster. This is the protocol that found the most-starred compression tool in the category making sessions fifty-three percent more expensive, because rewriting the conversation each turn destroys the provider's cache and everything gets re-billed at full price.

Why it matters to us: it is the only honest way to say "cheaper", and it is a trap that has already caught most of the field. We report the four billed token classes, not a token count.

Leakage across memory channels

no API cost

The only published harness that instruments the shared-memory channel between agents, rather than checking the final answer for secrets. Its finding is the one that shapes our design: nearly half of the leaks it measures pass through shared memory, and about forty percent are invisible to any audit that only inspects outputs — the information moves agent to agent and never appears in a reply.

Why it matters to us: it is the test our compartment rules exist to pass, and it grades the thing every vendor asserts without evidence.

Forgetting

no API cost

Maps one-to-one onto the four operations a store actually offers — write, recall, invalidate, purge — and checks that removal removes. Cheap to run, and it catches the failure where a fact is deleted but everything distilled from it survives, which is exactly the state our store is in today because nothing writes provenance.

Long-context recall

modest

Run only in the larger, unsaturated variant, and only for credibility: a system that scores well on change but badly on plain recall has traded one for the other. The small variant is saturated — one vendor's ninety-nine percent turned out to be eight variants scored as a pass if any of them succeeded, which the company itself described as a stunt.

The public leaderboard

free · opens 20 Sep

Add and search against a fixed interface, submitted to a third party who runs it. A hundred and thirty-six teams registered for the current cycle. It is the least informative of the set and the most useful politically: an independent listing nobody can accuse us of having designed.

Total for the full set: roughly seven hundred and fifty to three and a half thousand dollars of API spend, and eight to eleven engineering days for the adapters. The correctness exam alone is twenty-five to sixty dollars per seed — cheap enough that it runs after every significant change rather than once at the end.

The rule

What we do if the numbers are bad.

Publish them anyway, and say what they bound. If dependency extraction turns out to be unreliable, the result is "closure is limited by extraction quality, here is the measurement" — not a quiet change of subject to a metric that looks better. The reason to run public exams at all is that they can say no; a test that can only agree with us is decoration.

And our own numbers carry the same label we put on everyone else's until someone independent re-runs them: vendor-reported.
