The build

Every file that changes, and what goes in it.

This is the engineering plan for Tideline v2 — the modules written from scratch, the ones amended, and the defects closed on the way through. Paths are the memory core as it stands in Brigade today; the v2 work lands in a private package that implements the same interface, so the public store keeps working and the enterprise build is upstream Brigade plus one directory.

Phase 1 · days 4–8

The record every later phase writes against.

The current record already carries a value, a validity interval and an origin. Three fields are added and one is generalized. Everything else in the protocol is a consequence of these.

// the fact, after Phase 1
interface Fact {
  id           : FactId
  subject      : SubjectKey        // the slot this fact sets; drives supersession
  value        : string            // stored verbatim, never re-phrased
  validFrom    : Timestamp
  validTo      : Timestamp | null  // closed on supersession

  label        : Label            // NEW — who may read it. replaces origin
  provenance   : FactId[]         // EXISTS, unwritten — sources this came from
  dependsOn    : Dependency[]     // NEW — parents, each with its rule verbatim
  belief       : Belief           // NEW — true | false | contradicted | unknown

  writtenBy    : Principal         // NEW — the person, not the agent
  via          : Channel           // slack | tool | extraction | direct
  sourceType   : SourceType        // drives the write gate
}

interface Dependency { parent: FactId; rule?: string }  // rule kept as written
type Label = { readers: GroupRef[] }                // refs, never expanded lists

The label lattice

label.tsnew

Four functions and one resolver. join(a, b) returns the label whose readers are the intersection of both — the rule that makes a summary at least as private as its narrowest source. canRead(principal, label) resolves group references against the directory at query time, which is why removing someone from a team takes effect on their next question rather than after a re-index.

Named compartments are labels, not types: alice, team:payments, project:apollo, company. There is no separate personal store and no copy step between stores, because there are no two stores.

join(a, b)        // readers(a) ∩ readers(b)
leq(a, b)         // a is at least as private as b
canRead(p, label) // resolves groups live
readableBy(p)     // index predicate for recall

// company memory is just:
{ readers: ["group:everyone"] }

Reference model and conformance suite

model/ · conformance/new

A few hundred lines of deliberately naive TypeScript that implement the protocol with no indexes and no optimisation, so it is obviously correct by reading. It is the oracle. Beside it, property-based tests that generate random organizations, fact graphs and staff changes, then assert the eight rules under all of them — the recall of two stores that agree on what you may read is byte-identical; no sequence of derivations ever widens a label; purge leaves no descendant; audit replay matches the simulation.

// the shape of the check that matters most
property("withheld is indistinguishable from absent", (store, principal, query) => {
  const visible = store.filter(f => canRead(principal, f.label))
  return deepEqual(
    recall(store,   principal, query),   // full store
    recall(visible, principal, query),   // only what they may see
  )   // content, count, order, scores — and the time it took
})

Runs green against the reference model, red against today's store at exactly the gaps listed above. From here every line written for the rest of the month is checked automatically.

Phase 2 · days 9–14

Memory that stays correct when a fact changes.

This is the mechanism the whole field is missing, and the one that makes a self-updating company page possible. Two modules and one amendment.

Propagation on supersession

propagate.tsnew

When a fact is superseded, walk only its dependents — not the store. For each one: if the edge carries a rule, apply the rule to the new parent value and write the result, which supersedes the stale child through the machinery that already exists. If it carries no rule, close the child and mark it unknown, needing confirmation.

Rules are kept in the words they were written in. The published failure of the graph-based systems is that their extraction decomposes the sentence into triples and the conditional wording is lost, so nothing is left to apply later.

Cost is bounded by the number of reachable dependents, not the size of the store, and structured rules need no model call at all. That bound is the whole result: the only system that passes this exam today does it by having a frontier model rewrite the entire memory file on every ingest.

function propagate(old, next) {
  for (const child of dependents(old)) {
    const rule = edge(child, old).rule

    if (rule) {
      assert({
        subject: child.subject,
        value  : apply(rule, next.value),
        label  : join(child.label, next.label),
        provenance: [...child.provenance, next.id],
      })                       // auto-supersedes child
    } else {
      close(child)
      child.belief = "unknown"   // needs confirmation
    }
  }
}
// acyclic: checked when the edge is inserted

Four-valued belief

belief.tsnew

A fact is true, false, contradicted (two sources disagree and neither wins yet) or unknown (it was true, something upstream moved, and nothing has re-established it). Merging follows the algebra rather than a status flag, so "I no longer know" is a value the store computes. Today that state does not exist: a superseded dependent simply keeps its old value and gets recalled as current, which is precisely what the absence half of the exam catches.

Provenance producers

extract.ts · consolidate.ts · dream.tsamend

Every path that creates a fact from other facts starts writing the sources it used, and taking the join of their labels. The field is already in the record and nothing populates it, which is why deletion currently removes a fact but leaves everything distilled from it in place. This is also the number that bounds Phase 2: the published study shows one percent of missing edges leaves seventeen percent of invalidated content still reachable.

Phase 3 · days 15–18

Confidence from agreement, not from repetition.

Source reliability

trust.tsnew

The current rule promotes a belief to high confidence once it has been read three times. That means exposure validates truth: a fact becomes trusted by being useful, and a wrong fact that keeps getting retrieved becomes permanent. It is a measurable defect, not a style preference.

Replace it with a joint estimate. Sources — people, tools, channels, agents — each carry a reliability. Facts carry a confidence. Neither is known; both are inferred from where sources agree and disagree, iterated to a fixed point. Sources already carry labels, so this composes with the rest of the protocol rather than sitting beside it.

// iterate to convergence
repeat {
  for claim in claims:
    confidence[claim] = f(
      Σ reliability[s] for s in sources(claim)
    )
  for src in sources:
    reliability[src] = g(
      confidence[c] for c in claims(src)
    )
} until Δ < ε

Provable convergence, and it gives the admin console a real answer to "why does the company believe this" — which sources, agreeing how strongly.

Phase 4 · days 19–23

The layer that makes memory cheaper instead of more expensive.

Label-ordered assembly

brigade: system-prompt/assembler.tsamend

Blocks are emitted most-public first, with a boundary marker at each step up in privacy known only to that compartment's members. Two things follow. The company-wide block is byte-identical for every employee, so the provider caches it once for the whole organization and everyone after the first reads it at a tenth of the price. And a private block cannot be probed by someone outside its compartment, because they cannot construct the prefix that precedes it.

This has to live in the assembler. A memory server speaking the standard protocol has no say in how the host builds its request — which is the finding that decides the whole product shape.

// prompt, ordered by label
[ system + tools     ]  ← stable, cached
[ company memory     ]  ← same bytes for everyone
  boundary(team:payments)
[ team memory        ]
  boundary(alice)
[ personal memory    ]
[ conversation       ]
[ this turn          ]  ← only this is fresh

Injection under a budget

budget.tsnew

Instead of "send the top five", send the set that provably holds retrieval quality above a chosen bound for the dollars available, with a distribution-free guarantee. It turns the category's standard claim — "we cut tokens by N percent" — into something an enterprise can actually hold us to.

Billing ledger

eval/ledger.tsnew

Records the four classes a provider charges for — fresh input, cache write, cache read, output — per session, and reconciles the total against the actual bill. Everyone in the field reports tokens; the published study shows a thirty-eight percent cut in tokens raising the bill by seven percent, because cache traffic is most of the spend and compression breaks the cache. Without this ledger a cost claim is not checkable, including ours.

Plumbing the cost layer needs — the assembler's block ordering, an actor on memory events — goes upstream into public Brigade, because keeping it in a fork guarantees the fork drifts. The protocol, the propagation and the models stay private. Interfaces public, implementations private.
