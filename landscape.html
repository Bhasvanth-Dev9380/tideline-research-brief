The field

Ninety-one products. Four claims. Almost no evidence.

We read all four Y Combinator 2026 batches — six hundred and sixty companies — then swept Product Hunt, Show HN, funding announcements, investor portfolios and GitHub, and finally read the primary documentation of every enterprise incumbent. Everything below is quoted from a vendor's own page or a published paper. Where a vendor does not document something, it says so rather than counting against them.

On permissions

"Mem0 doesn't have that model, and honestly, most memory layers don't yet… If you genuinely need role-based permissions, that logic has to live in your own application layer."

mem0.ai — published 2 September 2026

That is the largest open-source memory layer in the category describing the state of the art, on the day we surveyed it. The one substantive counter-example is Zep's enterprise tier, which tags attributes at ingest, projects them onto derived nodes with intersection semantics, defaults to deny, and offers a report-only mode to test a policy before enforcing it. It is read-time and it is the strongest competitor design we found.

Everyone else offers scoping primitives — a container tag, a user id, a dataset, a bank — and leaves the policy to the customer. Two vendors document the failure themselves: one warns that its default tag-matching mode returns untagged memories to everyone, and another's own cookbook shows a query returning another agent's private preferences.

On cost

"So far, internal evals show about a 29% reduction in token spend and 21% reduction in task completion time."

Glen — YC launch, August 2026

We read the command-line tool this claim describes. The only public source for the number is a single blog post: a hundred pull requests replayed on one unnamed repository, five runs per arm, means reported, no raw data, no token-class definition, no variance, no independent replication.

More interesting is the mechanism. Since the release that shipped on the same day as the benchmark post, the tool injects no memory per prompt at all — it places a block at session start whose request carries no task context, and otherwise the agent has to call a search command itself. So the saving is not compression; it is the agent exploring less. Their own source comments record that the time saving inverted by twenty percent when they changed the wording of a single cautionary sentence appended to search results.

The incumbents

Everyone enforces on documents. Nobody labels what the AI makes.

We read the primary documentation for Glean, Microsoft 365 Copilot, Google Gemini Enterprise, Amazon Q Business, Notion, Atlassian Rovo, Slack, Salesforce Agentforce, Dust and Claude for Teams. The pattern is identical and so is the hole.

Two structural findings. First, propagation is rebuild-bound everywhere: identity syncs from thirty minutes, content syncs from three hours, and Microsoft documents that a visibility change on a large site "could take more than a week" to reflect in search and Copilot. Second, no vendor documents the existence question — whether a user can infer that a document they cannot read exists, from a result count, a ranking gap or a response time. It appears in none of the documentation we read.

What it adds up to

The uncontested ground.

Correctness under change

Measured at three and one percent across the field. One vendor claims forty, on its own site, from its own run. This is open ground with a public exam sitting on it.

Derived artifacts

Every incumbent enforces on documents and none labels what the model produces from them. Summaries, pages, memories and audit traces are where the leaks are, and it is a design gap rather than a bug queue.

Cost that is actually billed

Fifteen vendors claim token reductions. The public session-cost protocol found the most popular of them making sessions more expensive. Nobody reports dollars per solved task.

None of these is a marketing gap. Each is a mechanism that has to be built and then measured, which is what the twenty-five days are for.
